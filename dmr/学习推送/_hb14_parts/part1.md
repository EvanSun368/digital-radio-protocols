## 1. 为什么要写这篇手册（动机 + 现场对话）

前十三篇手册教你认病、交维与单机写频：贴纸 A–E 协议层，F 射频，G 实验室，H 话务，I 室分，J 写频/基线，K 电源，L 电梯井/车库。可现场还有一类「病」——**不是今晚空口才坏，而是批量/无线写那天把半个舰队写成另一本账，或空投落到海面**：

- 写频员：「OTAP 比有线快，今晚全网一起推。」——无试点闭环；失败面等于全网。  
- 班长：「先空口刷了，报表明天再导出。」——无完成账就放行；失败机混进勤务。  
- 夜班：「弱覆盖区那几台也一起 OTAP，反正会重试。」——空投落到海里；半成功半砖。  
- 新人：「密钥提示过期？先点继续试试。」——错钥/脏库开写；管理台与机上现服分裂。  
- 领导：「忙时空口写，用户感觉不到。」——空口争用挤压话务；手册09 假忙。  
- 射频同事：「覆盖差点，加功率再 OTAP。」——加功率是手册07/09 禁区；本篇也禁。  
- 仓库同事：「A 型号模板刷 B 型号，差不多。」——跨机型/跨重大固件互写；手册11 J 禁令批量不豁免。  
- 手册11 学过的人：「J 说先读后写——批量是不是可以豁免？」——**不可以。批量只放大事故半径。**

这几句背后是同一件事：

> **「大批量 / OTAP」这个词在现场至少有五个坑**：  
> **① M-批**：大批量有线写频作业编排——分批、试点、冻结窗、进度账；一口气通刷 = 事故预告  
> **② M-空**：OTAP/无线写频通道与覆盖窗口——信号、电量、勿关机、干扰/忙时窗；弱覆盖空投 = 落海  
> **③ M-钥**：OTAP 密钥 / 鉴权 / 管理台权限与数据库一致性——错钥、脏库、权限过大禁止开写  
> **④ M-试**：试点金机 / 小样本先验与业务闭环——紧急功能、组呼、登记；无小样本禁止全量  
> **⑤ M-界**：风险边界与拒写——忙时全网空口写、弱覆盖写、低电写、跨机型/跨重大固件互写、无完成报表就放行  
> 把 ①–⑤ 当成「OTAP 厂商功能自动搞定」或「出了事用手册01–05/11 单机分诊」，会把整队配置债与空口债留给下一班。

本篇目标：能背出**大批量写频与 OTAP 风险边界工作流**；会用新贴纸 **M（批量/OTAP）** 与五个子类；会填 **插页 M（R1–R8）** 和《本网大批量写频与 OTAP 风险边界卡》；能用「**空投物资 + 分批换装**」故事讲清岸边装船与空中补给；能拒绝「无试点全量、弱覆盖/低电 OTAP、错钥开写、忙时全网空口写、无报表放行」；自测过关后，回库把本网最近一次批量/OTAP 事件（脱敏到 L3）按本篇重对一遍。

**本篇硬禁令（写进脑子）**：不发明 ETSI 条款号；**不写真实批复频点、真实站号、真实个号、真实密钥、真实单位名进公开仓库**；**不教真实 OTAP 密钥生成/导出/攻击步骤**——只讲制度边界；不重写手册11 / 07–10 / 12–13 全文（只给指针）；**手册11 的 J 规则批量不豁免**；**不把 OTAP / 大批量写当协议或射频病的补丁，不把加功率当 OTAP 窗口补丁**；批量/OTAP 路径问题**主贴 M**，可挂 J/F/H/A/B，禁止把「空投失败」写成「用户不会用机器」；结案词用贴纸 M + 本网证据；公开厂商 OTAP 最佳实践 / 国安 OT 安全原则 / NIST 配置管理只借**精神与顺序**——**不背条款号当 ETSI**。

## 2. 总图 / 故事：批量写频像「空投物资 + 分批换装」

### 2.1 一句话：有线批量 = 岸边分批装船；OTAP = 空投——必须先证明投放区、油量、货封、试投，再舰队空投，且空投完必须有完成账

```text
   ┌──────────────────────────────────────────────────────────────┐
   │  舰队（本网终端机队）                                          │
   │                                                              │
   │   岸边码头 = 写频室 / 有线 CPS 工位（分批换装、可立即回滚）       │
   │   空投飞机 = 管理台 OTAP / 无线写频通道                         │
   │   投放区   = 强稳覆盖窗（M-空）                                  │
   │   油量     = 电量充足 + 用户已知勿关机（M-空）                   │
   │   货封     = 密钥/鉴权/库一致（M-钥）                            │
   │   试投     = 试点金机 + 小样本业务闭环（M-试）                   │
   │   完成账   = 成功/失败/未达报表；失败机有线回滚路径（M-界）       │
   │                                                              │
   │   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐     │
   │   │ 编排分批 │──▶│ 货封核钥 │──▶│ 试投闭环 │──▶│ 舰队空投 │     │
   │   │ (M-批)  │   │ (M-钥)  │   │ (M-试)  │   │(M-空/批)│     │
   │   └────┬────┘   └────┬────┘   └────▲────┘   └────┬────┘     │
   │        │             │             │              │           │
   │        │无冻结窗      │错钥脏库      │无小样本      │弱覆盖/低电 │
   │        ▼             ▼             │              ▼           │
   │   ┌─────────┐   ┌─────────┐       │         ┌─────────┐     │
   │   │ 进度账  │   │ 拒开写  │───────┘         │ 落海/半砖│     │
   │   │ (M-批)  │   │ (M-界)  │                 │ (M-界)  │     │
   │   └─────────┘   └─────────┘                 └────┬────┘     │
   │        ▲                                          │           │
   │   无完成报表禁止签字放行；失败机强制有线回滚（M-界）◀─┘           │
   │   忙时全网空口写 = 轰炸航线正忙还硬空投（禁）                      │
   └──────────────────────────────────────────────────────────────┘
```

口诀：

> **先试投，后全量；岸边可回滚，空投看投放区；货封不对不开舱；无完成账不放行。**  
> 无小样本就全网 OTAP = 没试投就空投整个舰队。  
> 弱覆盖/低电 OTAP = 物资落海——**先查 M-空，别先骂终端。**

### 2.2 「空投与换装」五段直觉（弱项短补，钉死）

| 段 | 像什么 | 运维直觉 | 本篇贴纸 |
|----|--------|----------|----------|

### 2.4 新贴纸 M：大批量写频 / OTAP（五个子类）

```text
                    ┌──────── 贴纸 M · 大批量/OTAP ────────┐
                    │  M-批  有线大批量编排：分批·试点·冻结窗·进度账 │
                    │  M-空  OTAP 通道：覆盖·电量·勿关机·干扰/忙时窗 │
                    │  M-钥  密钥/鉴权/管理台权限/数据库与现服一致   │
                    │  M-试  试点金机/小样本先验与业务闭环           │
                    │  M-界  拒写边界：忙时全网空口·弱覆盖·低电·跨机型 │
                    │        ·跨重大固件·无完成报表放行             │
                    └────────────────────────────────────────────┘
```

| 子类 | 一句话 | 典型拒写 / 拒放行触发 |
|------|--------|----------------------|
| **M-批** | 有线大批量必须分批+进度账 | 无分批计划；无冻结窗；进度只口头 |
| **M-空** | OTAP 必须在强稳覆盖+足电+勿关机窗 | 弱覆盖硬推；电量红区；用户不知勿关机 |
| **M-钥** | 密钥/权限/库与现服一致才开写 | 错钥提示仍继续；脏库；权限过大无人复核 |
| **M-试** | 无小样本业务闭环禁止全量 | 「先全网再抽测」；试点未测紧急功能/组呼 |
| **M-界** | 完成报表+失败有线回滚路径才放行 | 无成功/失败/未达表；失败机无有线路径；忙时全网空口写 |

**和贴纸 A–L / X 的咬合**：

- 批量/OTAP 路径问题**优先 M**；写后空口症状可挂 A/B/D/F/H，但结案词须写清「主贴 M + 次挂××」。  
- 单机有线变更气质挂 **J**；实验室验证挂 **G**；覆盖窗问题可挂 **F/I/L**；话务挤压挂 **H**。  
- 贴纸 **X**：只有「好像 OTAP 过了」的口述、无完成报表与试点记录时，先 X，**禁止结案为终端玄学，禁止放行**。

### 2.5 大批量 / OTAP 最小工作流（背下来）

```text
  ① 开作业单（M-批/M-界）：范围（机型族/固件族/台数脱敏）、窗口、影响、回滚负责人
  ② 货封检查（M-钥）：密钥/鉴权状态、管理台权限、库与现服一致；不对 → 拒开写
  ③ 禁令检查：忙时全网空口？弱覆盖硬推？低电？跨机型/跨重大固件模板？无试点？→ 停
  ④ 试投（M-试）：金机 + 小样本；登记/组呼/紧急功能/Grant 有声；不过 → 禁全量
  ⑤ 窗口执行：有线分批（M-批）或 OTAP 强稳窗（M-空）；进度账实时
  ⑥ 完成账（M-界）：成功/失败/未达；失败机进入有线回滚路径；无报表 → 拒放行
  ⑦ 过 → 更新现服索引与金机基线（指针 J）；不过 → 冻结窗 + 回滚 + 新开单
```

## 3. 核心交付：插页 M + 拒写/拒放行卡 + 与总三联单怎么写

### 3.1 什么时候贴 M（而不是先贴 J / A–F / H）

优先贴 **M** 的触发（命中一条就先走本篇）：

1. 一次作业涉及「大批量」有线写频（本网自定义门槛，例如超过试点规模）或任何 OTAP/无线写频窗。  
2. 「今晚全网一起推」「先刷完再抽测」。  
3. OTAP 在弱覆盖、低电、用户不知勿关机的窗口进行。  
4. 密钥/鉴权/库不一致仍有人要点「继续」。  
5. 忙时全网空口写，或用 OTAP 掩盖协议/射频病（含加功率叙事）。  
6. 跨机型或跨重大固件族模板通刷。  
7. 无成功/失败/未达报表就要签字放行；失败机没有有线回滚路径。

单机有线、有备份、有验证的常规变更——仍走 **手册11 贴纸 J**；本篇不替代 J，只放大到舰队尺度。

### 3.2 插页 M · 大批量 / OTAP（挂在总三联单或作业包首页后）

| 格 | 名称 | 你要填什么（脱敏 L3） |
|----|------|----------------------|
| R1 | 作业窗与对时 | 开写时刻、冻结窗、完成报表导出时刻、投诉窗是否同一时钟；对时差 |
| R2 | M 子类初判 | M-批 / M-空 / M-钥 / M-试 / M-界（可多选，标主贴） |
| R3 | 范围与分批 | 机型族·固件族·计划台数（脱敏）；分批序号；试点批大小 |
| R4 | 货封与权限 | 密钥/鉴权状态摘要（不写密钥值）；管理台账号角色；库一致性勾选 |
| R5 | 试投闭环 | 金机/小样本：登记□ 组呼□ 紧急□ Grant有声□；剧本名；结果 |
| R6 | 通道窗 | 有线工位 / OTAP；覆盖抽检；电量门槛；勿关机通知；是否避开忙时 |
| R7 | 完成账与回滚 | 成功/失败/未达计数；失败机有线回滚路径□；冻结/放行结论 |
| R8 | 证据包清单 | 「插页 M；作业单；试投表；完成报表脱敏；回滚记录；三联单号」 |

**插页组合**：M 常与 J（单机规则）、G（闭环）、X（证据不足）、必要时 A/B/F/H（写后症状）同挂。**不要**把「空投落海」写成「用户手贱关机」而不查 M-空通知是否到位。

### 3.3 「无试投 / 无完成账禁止放行」卡（贴写频室 / 网管）

在插页 M 的 R4–R7 没填之前，下面这些话不许进作业窗：

> 「OTAP 很快，不用试点。」  
> 「弱覆盖那几台一起推，失败会重试。」  
> 「密钥报警先忽略，继续。」  
> 「忙时写，用户感觉不到。」  
> 「跨机型模板差不多，通刷。」  
> 「报表明天再导，先让人上班。」  
> 「失败机让用户自己拿来有线修。」（无强制有线回滚路径 = M-界 拒放行）  
> 「加功率让 OTAP 稳一点。」  

**拒写 / 拒放行句式（背）**：

> 「插页 M 的 R5/R7 空着。先完成小样本业务闭环 + 导出成功/失败/未达报表，并为失败机准备有线回滚路径，再谈放行。忙时全网空口写与弱覆盖/低电 OTAP 禁止。」

### 3.4 和总三联单怎么写（接手册06）

| 三联单栏 | 批量/OTAP 事件怎么写 | 禁止写法 |
|----------|---------------------|----------|
| 表头对时 | 开写窗、完成报表窗、投诉窗同一窗 | 「大概夜里刷了」 |
| T 症状 | 「试点批 Grant 无声；全量已冻结」等可观察句 | 「OTAP 玄学」 |
| A 动作 | 「停空投；失败机有线回滚；修库后再开单」 | 「再推一遍碰运气」 |
| N 下一步 | 「重做 M-试；核对 M-钥；改窗口避开忙时」 | 「观察观察」无责任人 |
| A5 证据 | 「插页 M、试投表、完成报表脱敏、回滚单」 | 只口头「都成功了」 |
| 结论 | 主贴 M-×；次挂 J/A/B/F/H（若有） | 主贴写成干扰却无射频证据 |

## 4. 深潜：八条硬规则 + OTAP/批量直觉 + 假病禁令

### 4.1 八条硬规则（本篇钉子）

1. **先试点后全量；无小样本闭环禁止大批量**——试投不过，舰队不许起飞。  
2. **手册11 J 规则仍生效：先读后写、无备份禁写、验失败必回滚——批量不豁免**——舰队尺度只放大半径，不取消规矩。  
3. **OTAP 必须在强稳覆盖 + 电量充足 + 用户已知勿关机窗口进行**——弱覆盖/低电/未通知 = 拒写。  
4. **OTAP 密钥 / 管理台权限 / 数据库与机上现服一致；错钥 / 脏库禁止开写**——货封不对不开舱。  
5. **禁忙时全网空口大批量写；禁用 OTAP 掩盖协议/射频病（禁加功率叙事）**——空投不是止痛药。  
6. **跨机型 / 跨重大固件互写禁止；批量模板必须分机型分固件族**——「差不多」不是通行证。  
7. **无完成报表（成功/失败/未达）禁止签字放行；失败机强制有线回滚路径**——无签收账等于没交货。  
8. **公开包禁真实频点 / 个号 / 密钥 / 站名 / 单位名；脱敏 L3；不发明 ETSI 条款号**——教学与公开仓双禁。

### 4.2 OTAP / 批量直觉（不背厂商菜单）

```text
  要改舰队配置
        │
        ▼
  单机有线小改？──是──▶ 走手册11 J（本篇可挂 M-批 气质，主贴常仍是 J）
        │否（批量或 OTAP）
        ▼
  机型族/固件族拆分清楚？──否──▶ 拒写（M-界 / 规则6）
        │是
        ▼
  货封：钥/权/库一致？──否──▶ 拒开写（M-钥）
        │是
        ▼
  试投金机+小样本业务闭环过？──否──▶ 禁全量（M-试）
        │是
        ▼
  通道：有线分批 or OTAP 强稳窗+足电+勿关机+非忙时？──否──▶ 改窗（M-空/M-界）
        │是
        ▼
  执行 + 实时进度账
        │
        ▼
  完成报表有成功/失败/未达？失败机有有线回滚路径？──否──▶ 拒放行（M-界）
        │是
        ▼
  更新现服索引与金机基线（指针 J）→ 可谈放行
```

现场口诀：

> **先货封，再试投，后窗口，末完成账。**  
> 跳过试投的全网 OTAP = 没打样就量产。

### 4.3 有线分批 vs OTAP：何时选哪条船

| 维度 | 岸边有线分批（M-批） | 空投 OTAP（M-空） |
|------|---------------------|-------------------|
| 回滚速度 | 快：线在就能刷回 | 慢：失败机常需召回有线 |
| 覆盖依赖 | 低 | **高**——弱覆盖禁推 |
| 电量/勿关机 | 工位可控 | **必须**事先通知与门槛 |
| 忙时影响 | 主要占人工 | **占空口**——禁忙时全网 |
| 适合 | 高风险参数、大版本、失败代价高 | 已验证模板、强覆盖、可冻结勤务窗 |
| 共同前提 | 都要 M-试 + 完成账 + J 规则 | 同左 |

> 教学原则：**高风险变更优先岸边**；OTAP 是便利通道，不是豁免通道。

### 4.4 「假成功 / 假覆盖窗 / 假忙时 / 假协议」怎么认

| 假病外表 | 常见批量/OTAP 真因 | 错误处置 | 正确主贴 |
|----------|-------------------|----------|----------|
| 假成功 | 管理台显示「已发送」但无完成态；未达机当成功 | 直接放行上班 | M-界（无完成账） |
| 假覆盖窗 | 大堂强、车库/边缘弱仍统推 | 「重试就会好」 | M-空（次挂 F/I/L） |
| 假忙时 | OTAP 占空口造成掉话账 | 按手册09 加信道 | M-界（次挂 H） |
| 假协议 | 半成功参数导致登记/Grant 异常 | 立刻改鉴权/基站 | M（次挂 A/B；先回滚） |
| 假终端 | 低电关机中断 OTAP | 骂用户 | M-空（通知与门槛） |
| 假密钥无关 | 错钥仍「有的机能写」 | 继续推 | M-钥 停写 |

**三问快判（背）**：

1. **试投**：小样本业务闭环过了没有？（R5）  
2. **通道**：覆盖/电量/勿关机/非忙时是否成立？（R6）  
3. **完成账**：成功/失败/未达表在不在？失败机有线路径有没有？（R7）  

三问里有「否」，就**先写 M**；三问全「是」且仍有持续空口病，再进手册01–05/07/09。切记：半舰队异常优先冻结与回滚，不是先开同频工单。

### 4.5 假病禁令墙（与加功率叙事）

1. 禁止用 OTAP「先改一把试试」掩盖手册01–05 协议病。  
2. 禁止用加功率「照亮边缘台」来硬开 OTAP 窗。  
3. 禁止用「重试次数加满」代替覆盖治理。  
4. 禁止把完成报表缺失说成「系统忙稍后」。  
5. 禁止跨机型/跨重大固件「通刷省事」。  

### 4.6 和弱项加餐的衔接

12.5 kHz / 4FSK / 30 ms 两槽背熟，你才说得清：**批量/OTAP 改的是配置账本与空口占用窗口，不是调制台阶**。有人要用空口大批量写或加功率治覆盖/干扰时，回加餐 + 手册07/09/11 + 本篇八条硬规则。
