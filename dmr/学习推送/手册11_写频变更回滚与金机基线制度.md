## 1. 为什么要写这篇手册（动机 + 现场对话）

前十篇手册教你认病与交维：贴纸 A–E 协议层，F 射频层，G 实验室闭环，H 话务，I 室分/隧道交维。可现场还有一类「病」——**不是空口今天才坏，而是写频那天把整队写成了另一本账**：

- 写频员：「CPS 开了个空白工程，直接 Write 就行。」——机上旧配置被覆盖；回滚文件不存在。  
- 班长：「金机也有问题，肯定是基站。」——金机上周被人「临时改过」Hangtime，基线档案没更新；手册08 金机对照已经失锚。  
- 夜班：「先改一下队列超时，明天补单。」——三周后没人记得谁改的；投诉高峰变成手册09 假容量。  
- 新人：「这台机型差不多，把那台的 codeplug 拷过去。」——跨机型互写；半队登记失败气质（手册01）或 Grant 无声（手册02）。  
- 领导：「批量写完再抽测几台。」——抽测为零；全量写完才发现鉴权相关参数写错（手册05 气质）。  
- 交维同事：「手册10 说金机基线要入库——入库在哪？谁保管上一版？」——只有「现服」文件，书柜上没有「上一版」。

这几句背后是同一件事：

> **「写频」这个词在现场至少有五个坑**：  
> **① J-备**：变更前没读出、没另存备份——空白窗口直接 Write = 事故  
> **② J-基**：金机没有档案号/日期/配置摘要/验证记录——「好机」会漂移成「坏锚」  
> **③ J-变**：无变更单、范围不清、审批缺失——谁改什么、影响几台说不清  
> **④ J-验**：写后不做金机业务闭环——登记 / Grant 有声 / 上下行没证明就放行  
> **⑤ J-回**：验证失败舍不得回滚；历史版本只留一份或不留——书架上没有「上一版」  
> 把 ①–⑤ 当成「写完再慢慢调」或「出了事用手册01–05 分诊」，会把整队配置债留给下一班。

本篇目标：能背出**写频变更回滚工作流**；会用新贴纸 **J（写频/基线）** 与五个子类；会填 **插页 J（R1–R8）** 和《本网写频变更回滚与金机基线制度卡》；能用「**图书馆版本卡**」故事讲清现服与上一版；能拒绝「无备份就写、跨机型互写、写后不验、失败不回滚」；自测过关后，回库把本网最近一次写频/金机基线事件（脱敏到 L3）按本篇重对一遍。

**本篇硬禁令（写进脑子）**：不发明 ETSI 条款号；**不写真实批复频点、真实站号、真实个号、真实密钥、真实单位名进公开仓库**；不重写手册07 / 08 / 10 全文（只给指针）；**不把「加功率 / 乱拧 Hangtime」当写频补丁掩盖协议或射频病**；**跨机型 codeplug 禁止互写**（公开业余实践共识，作警示）；结案词用贴纸 J + 本网证据；配置管理公开理念可对齐 NIST CM-2(3)「保留先前配置以支持回滚」的**精神**——**不背条款当 ETSI**。

## 2. 总图 / 故事：写频像「图书馆版本卡」

### 2.1 一句话：变更 = 先保证书柜上有「现服」与「上一版」，再允许换书

```text
   ┌──────────────────────────────────────────────────────────┐
   │  图书馆（本网写频与金机制度）                               │
   │                                                          │
   │   ┌─────────────┐      ┌─────────────┐                   │
   │   │ 现服书架     │      │ 上一版 / 储备 │                   │
   │   │ （当前基线） │◀────▶│ （至少 N 版） │                   │
   │   └──────┬──────┘      └──────▲──────┘                   │
   │          │ 借出阅读            │ 换书失败→把旧书放回         │
   │          ▼                     │                           │
   │   ┌─────────────┐              │                           │
   │   │ 读出 → 另存  │──无备份──▶ 禁止 Write（J-备）            │
   │   │ 变更单审批   │──无单──▶ 禁止改（J-变）                  │
   │   │ 同机型 CPS   │──跨机型──▶ 禁止互写                     │
   │   └──────┬──────┘                                          │
   │          ▼                                                 │
   │   Write 到样机/金机抽测 → 手册08 气质闭环（J-验）            │
   │          │过                    │不过                      │
   │          ▼                      ▼                          │
   │   更新现服+归档上一版      回滚到上一版（J-回）             │
   │   再开批量/放行            关闭本单；新开变更单再来         │
   └──────────────────────────────────────────────────────────┘
```

口诀：

> **先读后写；书柜要有上一版；新书没验完，旧书不许扔。**  
> 空白 CPS 窗口直接 Write = 把孤本撕了还说「我记得内容」。  
> 金机基线 = 图书馆的**校对样本**，不是随便从阅览室拎来的一本。

### 2.2 「版本卡」三栏直觉（弱项短补，钉死）

| 栏 | 像什么 | 运维直觉 | 本篇贴纸 |
|----|--------|----------|----------|
| **现服** | 书架上读者正在借的那一版 | 当前全网/全队认可的配置摘要与金机档案 | J-基 |
| **上一版** | 柜台后面的储备本 | 验证失败立刻可还回；至少保留 N 个历史直觉 | J-回 |
| **草稿区** | 编辑室未上架的修改稿 | 只存在于带备份的工程文件 + 变更单；未经验证不上架 | J-备 / J-变 / J-验 |

> 公开配置管理常识（如 NIST SP 800-53 CM-2(3) 公开解释页所说）：**保留先前配置以支持回滚**。本篇只借这句精神——**不背条款号、不当 ETSI**。你只要记住：书柜里至少要能摸到「上一版」。

### 2.3 和手册08 / 10 的咬合（指针，不重写）

- **手册08 贴纸 G**：实验室「刺激→观察→判定→证据包」；本篇 J-验 **调用** 金机业务闭环气质，不重写六闭环全文。  
- **手册10 贴纸 I-交**：交维要写「金机基线存放」——本篇把「存放」升级成**档案号 + 版本卡 + 回滚演练**。  
- **手册06**：证据五要素与脱敏 L0–L3；公开仓/教学材料 **≥L2，教学例强制 L3**。  
- **手册01 / 02 / 05**：坏写频可表现为登记拒绝、Grant 无声、鉴权失败——先问「最近写过吗、有无备份可回」，再进协议分诊。  
- **手册07 / 09**：加功率、乱拧 Hangtime **不是**写频补丁；功率与话务另册。

### 2.4 新贴纸 J：写频 / 基线（五个子类）

```text
                    ┌──────── 贴纸 J · 写频/基线 ────────┐
                    │  J-备  变更前读出与备份               │
                    │  J-基  金机基线档案制度               │
                    │  J-变  变更单 / 范围 / 审批           │
                    │  J-验  写后验证（金机业务闭环）       │
                    │  J-回  回滚与失败关闭                 │
                    └────────────────────────────────────┘
```

| 子类 | 一句话 | 典型拒写 / 拒放行触发 |
|------|--------|----------------------|
| **J-备** | 先 Read→Save As→再 Edit；无备份禁止写 | 空白工程直接 Write；备份路径口头「在我U盘」却找不到 |
| **J-基** | 金机有档案号、日期、配置摘要、验证记录 | 「随便找台好机」当金机；基线过期未重验 |
| **J-变** | 谁改什么、影响几台/哪类参数、审批人 | 「临时改一下」无单；范围写成「相关机」 |
| **J-验** | 写后金机闭环：登记/Grant有声/上下行 | 写完直接批量；无证据包装进手册06 |
| **J-回** | 验失败必须回滚；保留至少 N 版历史 | 「再调两下就好」代替回滚；旧版已删 |

**和贴纸 A–I / X 的咬合**：

- 变更过程中**优先 J**；写完才出现的登记/Grant/鉴权症状，可**挂**手册01/02/05，但先查最近写频单。  
- 实验室验证挂 **G**；现场射频病挂 **F**；话务挂 **H**——**禁止**用写频乱拧掩盖。  
- 贴纸 **X**：只有「好像写过」的口述、无备份路径与验证表时，先 X，**禁止继续 Write / 禁止结案为终端玄学**。

### 2.5 写频变更最小工作流（背下来）

```text
  ① 开变更单（J-变）：范围、机型、参数类、影响台数、窗口、审批
  ② 读出当前配置并另存备份（J-备）：文件名含机型+日期+变更号（脱敏）
  ③ 同机型、匹配 CPS/固件气质；跨机型 → 停
  ④ 在草稿区编辑；金机或样机先写（禁止一上来全量）
  ⑤ J-验：手册08 气质闭环（登记/Grant有声/上下行；需要时挂射频三过指针）
  ⑥ 过 → 更新现服版本卡 + 把旧现服移入「上一版」架（J-基/J-回）
     不过 → 立即回滚（J-回）；关闭本单；原因进证据包；新开单再来
  ⑦ 批量仅在样机验证通过后；批量中抽检；结束归档（手册06 脱敏）
```

## 3. 核心交付：插页 J + 拒写卡 + 制度卡预告

### 3.1 什么时候贴 J（而不是先贴 A–F）

| 现场原话 / 现象 | 先贴 | 说明 |
|-----------------|------|------|
| 「CPS 空白窗口，直接写吧」 | **J-备** | 先读出；无备份禁止写 |
| 「金机也登不上，基站坏了」 | **J-基** 再手册08 | 金机是否仍是档案金机？ |
| 「夜里临时改了 Hangtime」 | **J-变** | 无单 = 制度失败 |
| 「写完了，用户说有的有声有的没有」 | **J-验** → 可挂手册02 | 先问验证表在哪 |
| 「新配置不行，旧文件删了」 | **J-回** | 书柜无上一版 |
| 「用 A 型号文件刷 B 型号」 | **J-备/J-变** 禁令 | 跨机型禁止互写 |
| 写后大量登记拒绝 / 鉴权失败 | **J** 查最近变更 + 手册01/05 | 先回滚窗口，再深分诊 |
| 覆盖差却要改写频加功率 | **拒**；指针手册07/09 | 不是本篇合法变更 |

### 3.2 插页 J · 写频 / 基线（挂在总三联单或变更包首页后）

| # | 格 | 填什么（教学虚构例） |
|---|----|----------------------|
| R1 | 主子类 + 次子类 | 「主 J-验 / 次 J-回」（或 J-备 / J-基 / J-变） |
| R2 | 变更范围 | 「机型族 T；参数类：Hangtime·队列；影响教学台数 N；非全网信道表」 |
| R3 | 备份证明 | 「读出时间；备份路径（脱敏）；文件哈希/大小；保管人」 |
| R4 | 金机锚 | 「金机档案号 G-xx；基线日期；与手册08 对照是否过期」 |
| R5 | 审批与 CPS | 「变更单号；审批人；CPS 版本与机型匹配□；跨机型□否」 |

### 3.3 「无备份禁止写」卡（贴写频室）

```text

  × 「空白工程直接 Write」           （缺读出与备份）
  × 「机型差不多，文件通刷」         （跨机型禁止）
  × 「先写上，验不验明天再说」       （写后未验证=未完成）

  ✓ Read → Save As → 变更单审批 → 样机写 → J-验 → 过再批量

```

## 4. 深潜：八条硬规则 + 基线档案 + 回滚直觉

### 4.1 八条硬规则（本篇钉子）

1. **先读后写**：空白 CPS 窗口直接 Write = 事故。  
2. **无备份禁止写频**。  
3. **金机基线 ≠ 随便找一台好机**：要有档案号、日期、配置摘要、验证记录。  
4. **写后未验证 = 变更未完成**（即使「写成功」弹窗已出）。  
5. **验证失败必须回滚**；回滚后再开新变更单（禁止在失败稿上连续乱拧）。  
6. **不把「加功率 / 改 Hangtime 乱拧」当写频补丁**掩盖协议/射频病（指针手册07/09）。  
7. **跨机型 codeplug 禁止互写**（公开业余实践共识，作警示）。  
8. **脱敏**：公开仓/教学材料不得含真实频点、个号、密钥、站点名（手册06 L2/L3）。

### 4.2 金机基线档案（J-基）最低字段

| 字段 | 为什么要 | 教学填写例（L3） |
|------|----------|------------------|
| 档案号 | 可引用、可审计 | G-11-03 |
| 机型族 / 固件气质 | 防跨机型误用 | 机型族 T；固件标签（脱敏） |
| 配置摘要 | 不打开文件也能知道「这版改过什么类」 | 「信道逻辑表批次 B；Hangtime 默认档；鉴权相关：开」 |
| 基线日期与有效期 | 大变更后要重锚 | 建档日；写频批次变更后重验 |
| 验证记录指针 | 接手册08 | 「闭环①③ 过；证据包号 …」 |
| 存放位置 | 接手册10 I-交 | 「制度柜 / 双人权限路径（脱敏）」 |
| 上一版指针 | 回滚入口 | 「上版档案号 G-11-02」 |

> **漂移警告**：金机若被「临时改一下」却未更新档案，手册08 的金机对照会**系统性说谎**。发现漂移 → 先隔离该机金机资格 → 从上一版重刷 → 重跑验证 → 再授牌。

### 4.3 变更单范围怎么写（J-变）

合法范围描述（教学）：

- 机型族、台数上限、是否含金机、是否含车载/中转相关终端。  
- 参数类勾选：**信道逻辑 / CC / 时隙 / Hangtime / 队列 / 鉴权相关 / 其他（写明）**——**不写真实频点**。  
- 窗口：维护窗 / 夜间；回滚负责人（与写入员可分离，像「双钥匙」：一把写、一把确认回滚包在）。  
- 审批：班长/网管（按本网制度）；无审批签名 → 拒写。

非法范围：

- 「相关机都写一下」；「先写上领导再补签」；「用邻网文件改改」。

### 4.4 写后验证最小包（J-验，调用手册08 气质）

不重写六闭环全文。最低业务包：

```text
  刺激 → 观察 → 判定 → 证据包
  · 金机/样机先：登记或等价附着证明
  · Grant → 有声（接手册02 四问气质，不展开）
  · 上下行抽测（听得到且打得出）
  · 需要时：手册08 射频三过分流 / 减敏——有条件做，没条件诚实写「未做」
  · 金机对照：变更后金机仍应「过」；金机不过 → 先疑写频/剧本/台架，禁止宣告「基站挂了」
```

**批量规则**：样机未过，禁止全量；全量过程中按比例抽检；抽检失败 → 停写 + 回滚已写样本策略按本网预案（教学：优先停，再按清单回滚）。

### 4.5 回滚与版本保留（J-回）

```text
  验失败
    → 立即用上一版备份 Write 回样机/已写机（按清单）
    → 再跑同一验证剧本应回到「过」
    → 关闭本变更单（结论：回滚成功/回滚失败升级）
    → 新问题用新变更单；禁止在失败稿上无限「再试一版」
  版本保留直觉：
    至少能摸到「现服 + 上一版」；更好是保留 N 个历史基线（N 由本网定，教学建议 ≥2 个上一版）
    对齐公开理念：保留先前配置以支持回滚（NIST CM-2(3) 精神，不背条款）
```

### 4.6 CPS 版本与文件类型陷阱

| 陷阱 | 现象气质 | 制度动作 |
|------|----------|----------|
| CPS 与机型不匹配 | 打不开 / 写入手破坏 | R5 强制勾选匹配 |
| 固件与 codeplug 世代错位 | 部分功能鬼畜、登记怪 | 变更单写明固件气质；金机先验 |
| 只备份「工程名」不备份可读出文件 | 回滚时找不到真文件 | J-备 要求可打开证明 |
| 联系人/密钥区误导入公开材料 | 泄密 | 手册06 脱敏；教学仓禁止密钥 |

## 6. 工作实例（10 个厚例，均教学虚构、已脱敏到 L3）

### 例 1 · 「空白 CPS 直接 Write」→ J-备

现象：写频员打开新工程，未读出，直接写一台样机。  
观察：机上原队列/Hangtime 被默认值覆盖；磁盘无读出备份。  
判定：主 **J-备**。立即停写；尝试从其他同批次机读出抢救；本单作废。  
教训：空白窗口 Write = 事故入口，不是效率技巧。

### 例 2 · 「机型差不多，文件通刷」→ 跨机型禁令 + J-变

现象：用机型族 A 的 codeplug 写机型族 B。  
观察：部分机登记失败气质（手册01）；部分 Grant 无声气质（手册02）。  
判定：违规互写；停批量；按机型族分别从合法备份恢复。  
教训：公开业余实践也反复警示——**跨机型禁止互写**；制度上写进封面拒写门槛。

### 例 3 · 「夜里临时改 Hangtime，明天补单」→ J-变

现象：投诉「通话切断快」；有人改长 Hangtime。  
观察：无变更单；金机档案摘要未更新；三周后无人记得原值。  
判定：**J-变** 失败；现服与档案不一致（次 **J-基**）。  
动作：读出当前、与上一版比对、补追溯单、重验；禁止再「临时永久化」。

### 例 4 · 「金机漂移：值班室那台被临时改过」→ J-基

现象：手册08 闭环① 金机不过，班长要申告基站。  
观察：金机档案日过期；中间有无单写频痕迹。  
判定：**J-基** 失锚。剥夺金机资格 → 上一版重刷 → 重验授牌。  
教训：金机基线 ≠ 能开机的机器。

### 例 5 · 「样机验证失败，仍想批量」→ J-验 + J-回

现象：样机 Grant 无声；工程师说「用户机也许没事」。  
观察：插页 J 的 R6 为不过；无回滚记录。  
判定：主 **J-验**；动作必须 **J-回**。  
结果：回滚后样机恢复有声；新开单查 CHAN/时隙/门牌类参数（指针手册02/04，不展开）。

### 例 6 · 「全量写完再抽测」→ J-验（批量无样检）

现象：80 台写完后才发现鉴权相关参数批次错误（手册05 气质）。  
观察：变更单写了「写后抽测」但抽测栏空白。  
判定：**J-验** 制度失败；成本从「1 台回滚」变成「队列回滚」。  
动作：停用受影响队；按备份清单分批回滚；复盘强制「样机过→再批量→批量中抽检」。

### 例 7 · 「CPS 版本与文件不匹配」→ J-变 / J-备

现象：旧 CPS 打开新固件气质导出的文件，字段错位。  
观察：写入后信道逻辑错乱；备份是「另存的坏草稿」而非写前读出。  
判定：R5 匹配失败；写前读出备份仍可用于回滚。  
教训：另存草稿 ≠ 写前读出备份；两者都要。

### 例 8 · 「基线文件丢失，书柜空了」→ J-回 / J-基

现象：要回滚，网盘链接失效；本地只剩现服坏稿。  
观察：无上一版；无离线副本；交维时 I-交 写过「基线存放」但未双人校验。  
判定：**J-回** 无能；从同批次未改机紧急读出抢救，并重建版本卡。  
教训：基线要**可打开的双份**（教学：在线+离线），不是「曾经上传过」。

### 例 9 · 「临时改一下」变成永久 → J-变 + J-基

现象：为演示改了演示机参数；演示机后来被误标为金机。  
观察：档案摘要与现服不一致；实验室结论反复横跳。  
判定：演示机不得冒充金机；临时变更必须有**自动回滚时限**或演示后强制回刷。  
制度：临时窗口写进变更单；逾时未关单 = 审计红灯。

### 例 10 ·（对照）实验室 G 过 vs 车队写坏后现场乱 → 不是射频玄学优先

现象：台架金机闭环 G 过；车队批量写后现场登记/有声混乱。  
观察：最近有写频单；备份存在；样机验证栏曾「过」但批量文件与样机文件哈希不一致（用了另一草稿）。  
判定：主 **J-备/J-验**（文件一致性）；回滚车队至写前读出版；实验室 G 过支持「别先砸基站/别先加功率」。  
教训：样机过只对**同一文件哈希**负责；换草稿要重验。

### 6.5 写频对齐会：20 分钟议程

```text
  1) 本周变更单清单：进行中 / 已关闭 / 回滚单（3 min）
  2) Top 拒写原因：J 子类分布（4 min）
  3) 金机档案抽查：过期？漂移？上一版可打开？（5 min）
  4) 误证统计：空白写、跨机型、无验批量、失败不回滚（4 min）
  5) 与手册08/10 对齐：实验室锚 + 交维基线存放（4 min）
```

| 28 | 双钥匙直觉 | 写入与回滚确认可分离 | 不是真要两把金属钥匙 |

**易错观念十条**：

1. 「Write 成功 = 变更完成」→ 缺验证就不算完成。  
2. 「金机 = 能开机的好机」→ 要档案与验证。  
3. 「备份在微信里发过」→ 要可打开可回滚的归档。  
4. 「机型差不多可以通刷」→ 禁止。  
5. 「验失败再调调更快」→ 必须先回滚再新开单。  
6. 「Hangtime 拧大能治覆盖」→ 否；挂手册07/09。  
7. 「加功率顶写频事故」→ 禁止掩盖。  
8. 「历史版本占空间，删光」→ 书柜空了无法回滚。  
9. 「临时改不用开单」→ 临时最容易变永久债务。  
10. 「实验室 G 过就可以无视写频单」→ 现场批量文件可能不是同一哈希。

**题 1.** 贴纸 J 五个子类各用一句话说明；各举一个拒写/拒放行触发。

**题 10.** 列出封面拒写门槛至少五条（与 §7.1 对齐）。

### 参考答案

1. **J-备**读出备份；**J-基**金机档案制度；**J-变**变更单范围审批；**J-验**写后闭环验证；**J-回**失败回滚与版本保留。触发例：无备份；金机无档案；无单；未验要批量；上一版打不开。  
2. 空白写会覆盖机内唯一配置且无回滚源。顺序：Read→Save As→变更单→Edit→样机 Write→验证→过再批量。  
3. 档案号、日期、配置摘要、验证记录（及存放/上一版指针）。能开机≠已知良好未漂移。  
4. 登记（或等价附着）、Grant 有声、上下行可达；证据进包。  
5. 失败稿连续拧制造不可审计漂移；先回滚证明能回到绿，再新开单。  
6. R3 挡「无备份」；R4 挡「假金机」；R5 挡「无审批/跨机型」；R6 挡「写完不验」。  
7. 字段/能力不兼容，制造系统性幽灵故障；常表现为手册01 登记、02 Grant 无声、05 鉴权等气质。  
8. 现服=架上在用的书；上一版=柜台储备；草稿=编辑室未上架；新书没验完旧书不许扔。  
9. J-基 提供档案锚；手册08 用该锚做对照。漂移：隔离资格→上一版重刷→重验授牌。  
10. 无备份；无变更单/审批；跨机型；金机无档案/过期；未验要批量；拒回滚/上一版不可开；加功率或乱拧 Hangtime 掩盖；脱敏失败（答出≥5 条即可）。
