## 1. 为什么要写这篇手册（动机 + 现场对话）

前八篇手册教你认病：贴纸 A–E 是协议层，贴纸 F 是射频层，贴纸 G 是实验室闭环章。可现场还有一类投诉，**看起来像终端或覆盖，骨子里是「今晚房间不够」**：

- 用户：「一直排队，抢不到信道。」——网管同时段多路 QACK（Queued-for-resource），业务时隙全满。  
- 调度：「忙音！金机也忙。」——金机也忙在高峰 = **容量证据**，不是「金机坏了」。  
- 班长：「加了 `*8` 优先，怎么还是慢？」——规范允许 TSCC 管优先级队列，但**怎么管不规定**（第 38 课）；本网可能根本没开优先级排队。  
- 网管：「短信一多，登记也慢。」——UDT/短信跑在 **TSCC** 上，不占业务信道，但**会吃掉控制信道时隙**（第 39 课）。  
- 新人：「那肯定是干扰，手册07 走一圈。」——五格梯子能量/SYNC/CC/BER 都过，还在高峰集体忙 → **先别贴 F**。  
- 站务：「把功率开大一点，感觉会好。」——**加功率不会加信道**；功率打歪了还可能制造 F-互。  
- 领导：「我们不是双时隙吗？怎么还挤？」——双时隙只是「一条车道变两扇门」；站上如果只有 1 条物理业务信道，最多两路；Hangtime 还在占着其中一扇。

这几句背后是同一件事：

> **「忙」这个词在现场至少有五个意思**：  
> **① H-忙**：业务资源真满——没有空闲 Payload 时隙可 Grant  
> **② H-排**：系统愿意排队——你收到的是 QACK，不是最终拒绝  
> **③ H-控**：控制信道挤爆——Aloha/登记/短信/USBD 风暴把 TSCC 塞满  
> **④ H-配**：配置在「造忙」——Hangtime 过长、信道太少、Non-Dedicated TSCC 饿死、队列策略没开  
> **⑤ H-优**：优先级/紧急抢占被误解——拨了优先码 ≠ 标准强制插队  
> 把 ①–⑤ 当成「终端故障」或「覆盖差」，会带着整班人去拧错旋钮。

本篇目标：能背出**话务分诊工作流**；会用新贴纸 **H（话务/容量）** 与五个子类；会填 **插页 H（R1–R8）** 和《本网话务与容量分诊卡》；能用旅馆前台故事讲清 **控制容量 ≠ 业务容量**；能用 Erlang-B 直觉（不重数学）判断「要不要加信道」；自测过关后，回库把本网最近两张「高峰忙」工单（脱敏到 L3）按本篇重写。

**本篇硬禁令（写进脑子）**：不发明 ETSI 条款号；**不写真实批复频点、真实站点名 / 站号、真实个号、真实密钥进公开仓库**；不重讲手册01 Reason 剧本、手册04 Hunt、手册05 鉴权算术、手册08 六闭环全文（只给指针）；**不把「开大功率」当扩容手段**；不把厂商专有集群名（Capacity Plus / XPT / …）当成 ETSI 强制术语——本篇只借它们讲「容量直觉」，结案仍用贴纸 H + 本网证据。

## 2. 总图 / 故事：旅馆前台 + 客房，再加「今晚订满了」

### 2.1 一句话：容量分诊 = 先问「满的是前台还是客房」

把第 31 课旅馆故事接到「订满」场景：

```text
   ┌─────────────────────────────────────────────────────────┐
   │  旅馆（一个站点 / 一个逻辑系统）                          │
   │                                                         │
   │  前台 TSCC          走廊/电梯           客房 Payload      │
   │  · Aloha 告示        · 改频搬家         · 真正说话        │
   │  · C_RAND 按铃       · Grant 小票       · 两扇时隙门      │
   │  · QACK 排队条                          · Hangtime 占房   │
   │  · 短信 UDT 小货车                      · 说完才退房      │
   │                                                         │
   │  前台挤爆 = H-控     小票发不出=看哪边满   客房订满 = H-忙 │
   │  队列策略怪 = H-配 / H-优                                 │
   └─────────────────────────────────────────────────────────┘
```

口诀：

> **先分「前台忙」还是「客房忙」。**  
> 前台忙：登记慢、短信堆积、Aloha 稀疏或风暴、Grant 迟迟不来但业务侧其实有空房。  
> 客房忙：清晰的 QACK Queued-for-resource / 资源类 NACK，网管显示业务时隙占用打满。  
> 两边都要看；只盯射频或只盯一台手台，永远分不清。

### 2.2 双时隙容量直觉（弱项短补，钉死）

```text
  一条 12.5 kHz 物理信道
        │
        ├── 时隙 1（30 ms）── 一路半双工话 / 或控制角色
        └── 时隙 2（30 ms）── 另一路半双工话 / 或控制角色
        一轮 = 60 ms

  站上若有 N 条物理业务信道 → 理论峰值约 2N 路同时半双工话
  （还要扣：Dedicated TSCC 占用、Hangtime、数据占用、维护闭塞……）
```

| 误解 | 纠正 |
|------|------|
| 「我们上了 DMR，容量自动翻倍，永远不忙」 | 翻倍是相对**同带宽模拟一路**；用户数、通话时长、Hangtime 一涨，照样 Erlang 打满 |
| 「双时隙 = 两路永远可用」 | 一路可能被 Dedicated TSCC、数据、Hangtime、故障闭塞吃掉 |
| 「忙了就加功率」 | 功率改的是覆盖与干扰边界，**不加时隙** |
| 「金机也忙 = 基站射频坏了」 | 高峰金机也忙，优先当 **H-忙 / H-配** 证据，再决定要不要走手册07/08 |

### 2.3 控制容量 vs 业务容量（两本账）

| 账本 | 装什么 | 挤爆时用户怎么说 | 空口/网管常见像 |
|------|--------|------------------|-----------------|
| **业务容量** | Payload 时隙上的语音/分组数据 | 「排队」「忙音」「抢不到信道」 | QACK `Queued-for-resource`；业务占用 100%；Grant 延迟后终于来或变 NACK |
| **控制容量** | TSCC 上的 Aloha / 登记 / Grant / UDT 短信 / USBD / Stun… | 「登记慢」「短信一多全都卡」「按了没反应过一会才嘟」 | 控制信道利用率高；登记时延拉长；短信队列堆积；Aloha 参数被风暴打乱 |

> 第 39 课钉过：Stun / DGNA / 短信 **全在 TSCC，不占业务信道**——所以「业务空着但全网发呆」完全可能，那是 **H-控**，不是 H-忙。

### 2.4 新贴纸 H：话务 / 容量（五个子类）

```text
                    ┌──────── 贴纸 H · 话务/容量 ────────┐
                    │                                    │
         ┌──────────┼──────────┬──────────┬──────────┐  │
         ▼          ▼          ▼          ▼          ▼  │
      H-忙       H-排       H-控       H-配       H-优  │
   资源满/无空   排队中     控制挤爆   配置造忙   优先误解 │
   Payload槽    QACK等待   Aloha/短信  Hangtime/  队列未实现│
                非最终拒绝  登记风暴   信道过少/  或紧急抢占│
                                      Non-Ded饥饿 预期落差  │
                    └────────────────────────────────────┘
```

| 子类 | 一句话 | 典型一手证据（教学） | 常见误贴 |
|------|--------|----------------------|----------|
| **H-忙** | 客房订满，发不出新 Grant | 同时段业务时隙全占用；资源类忙/拒绝；多用户同时 | F-弱、终端故障 |
| **H-排** | 系统说「排上了」 | QACK（如 Queued-for-resource / Queued-for-busy）；随后可能 Grant | 把 QACK 当故障狂按 PTT |
| **H-控** | 前台窗口堵死 | 控制利用率高；登记/短信时延；业务侧仍有空闲 | H-忙、覆盖 |
| **H-配** | 旋钮在造忙 | Hangtime 过长；可用信道数少；Non-Dedicated 饥饿；队列/负载参数怪 | 「基站老化」空锅 |
| **H-优** | 优先/紧急预期落空 | 拨了优先修饰但队列策略未开；紧急抢占未配置 | 手台坏、写频坏 |

**和贴纸 A–G 的咬合**：

- 先排除「单机协议病」A–E（登记拒绝、Grant 无声、Stun/短信话术、Hunt、鉴权）——**若只有一台偶发，优先 A–E，不先贴 H**。  
- 五格梯子（手册07）射频三过之后，若症状是**高峰、多人、金机也中招** → 进入 H。  
- 贴纸 G（手册08）：容量问题**很难在无负载台架上复现**；台架 G 过、现场高峰挂，是支持 H 的旁证，不是矛盾。  
- 贴纸 X：只有用户口述「好卡」而没有占用率/QACK/时段统计时，先 X，别硬贴 H。

## 3. 核心交付：分诊工作流 + 插页 H + 本网分诊卡

### 3.1 话务分诊工作流（每张「忙/排队」工单照念）

```text
  ① 定性：时段、站/逻辑系统、人数规模、金机是否同样、用户原话
  ② 分流：单机偶发？→ A–E；射频可疑？→ 五格梯子；否则进 H
  ③ 两本账：控制利用率 / 业务时隙占用 / 队列长度（网管一手）
  ④ 空口抽样：有无 QACK / 资源类 NACK / Grant 延迟 / Aloha 异常
  ⑤ 定子类：H-忙 / H-排 / H-控 / H-配 / H-优（可主+次）
  ⑥ 动作：短反例（降 Hangtime 试验？限短信风暴？）须维护窗
  ⑦ 证据包：插页 H + 脱敏占用曲线 + 总三联单
  ⑧ 禁止：加功率当扩容；未看占用就换机；把 QACK 当故障重装固件
```

### 3.2 子类判定速查（心脏表）

| 若你看见… | 优先子类 | 下一刀 |
|-----------|----------|--------|
| 业务占用打满 + 多用户 QACK 资源排队 | H-忙（主）+ H-排（次） | 统计忙时 Erlang 直觉；评估加信道/拆站/限时业务 |
| QACK 后最终 Grant，用户只是嫌慢 | H-排 | 查队列超时、用户教育「别狂按」；看是否可接受 GoS |
| 业务占用低，但登记/短信时延炸 | H-控 | 查短信/UDT/登记风暴；临时限短数据；查 Aloha 负载 |
| Hangtime 显著长于话音间隙、空闲时隙被「礼貌窗」长期占 | H-配 | 维护窗评估 Hangtime；核对可用信道数与闭塞列表 |
| Non-Dedicated：一有话务控制就「让路」导致叫号失败 | H-配 | 确认站点模式；评估是否需要更稳的控制形态（本网架构决策） |
| 用户拨优先/紧急，空口有优先比特但队列无插队 | H-优 | 查网管是否实现优先队列/抢占；对用户诚实说「本网策略」 |
| 只有一台、非高峰、金机同点正常 | **不要贴 H** | 回 A–E / F / G |

## 4. 深潜：Erlang 直觉 + DMR 容量特有坑

### 4.1 Erlang-B 直觉（不重数学，只求会用嘴说）

电信话务里常用 **Erlang（爱尔兰）** 衡量「有多忙」：

- **1 Erlang** ≈ 一条信道被连续占用 1 小时，或等价地「平均同时有 1 路在通话」。  
- **Offered load（落入负荷）** ≈ 忙时呼叫次数 × 平均占用时长（化成小时）。  
- **信道数 C**：你有多少条可同时承载的「客房门」（DMR 里近似「空闲可 Grant 的业务时隙数」）。  
- **Erlang-B**：假设**不愿排队、来了发现满就走**（Blocked Calls Cleared）时，呼叫被挡的概率——也叫 **GoS（Grade of Service，服务等级）**。例如 GoS=0.02 表示忙时约 2% 呼叫会被挡。

白话旅馆版：

```text
  今晚平均同时想住房的人（A Erlang）
            +
  你有几间空房（C）
            ↓
  订不到房的概率（阻塞概率 / GoS）
```

**DMR 现场怎么用（不用算阶乘）**：

1. 从网管拉**忙时**「平均同时占用时隙数」≈ 粗粒度 Erlang。  
2. 数清**真正可业务的时隙数**（扣 TSCC、闭塞、数据专用）。  
3. 若忙时经常打满且 QACK/拒绝扎堆 → 阻塞已经「摸得着」，别再用感觉。  
4. 要粗算「再加 1 条物理信道（+2 时隙）够不够」，用公开 Erlang-B 表/教程对照数量级即可（§10 外链）；**本篇不要求你手算阶乘**。

| 词 | 现场白话 | 别混成 |
|----|----------|--------|
| Offered load | 有多少通话需求砸进来 | 已接通数（那是 carried） |
| Blocking | 满了被拒/走 | 覆盖不好听不见 |
| Queueing（Erlang-C 气质） | 满了先排队 | 「系统死机」 |
| GoS | 你答应领导的「忙时最多多忙」 | BER / RSSI |
| Busy hour | 最忙的那一小时窗口 | 「全天平均」——平均会骗你 |

> **全天平均占用 30%、忙时 98%**——只报平均的人，会坚定地认为「不需要扩容」。话务分诊**认忙时，不认被平均稀释的安慰剂**。

### 4.2 DMR 特有：2 槽、Hangtime、TSCC、QACK、优先、Non-Dedicated、短信

#### 4.2.1 每 12.5 kHz 两槽——上限直觉

- 模拟同带宽常常「一路占死一条信道」；DMR TDMA 让你在同带宽拿到**两扇门**（DMR Association 公开材料的核心卖点之一）。  
- 集群再把多门共享给多组用户——**共享带来 trunking efficiency（集线效率）**：同样多门，合池比拆成小组独占更能扛突发（经典 trunking 课都会演示：10 门合用 > 两组各 5 门）。  
- 现场含义：扩容优先问「能不能把业务时隙合池、减少人为分割」，而不是先喊买站。

#### 4.2.2 Hangtime 占用的是槽，不是「礼貌」本身

第 26 课：Hangtime 是 EOT 后中继短暂保留同组优先窗。容量视角：

- Hangtime **越长**，平均占用 ↑，同等呼叫次数下 Erlang ↑。  
- 「没人说话却占着组」在忙时 = **H-配 嫌疑**。  
- 改 Hangtime 是**维护窗配置动作**，须记基线、可回滚（下一篇候选「写频/配置回滚」会咬这里）。

#### 4.2.3 TSCC 共享：控制也是稀缺品

- **Dedicated TSCC**：专职前台，业务客房更干净，但要占用控制资源。  
- **Non-Dedicated TSCC**：控制与业务共享形态，省信道，但话务一高，前台可能「给客房让路」→ 叫号/登记变差 → **H-配 / H-控** 交界。  
- 学口径：先问清「本站是专用控制还是共享控制」，再解释「为什么业务空着还会登记慢」。

#### 4.2.4 QACK vs 忙拒绝（接第 34 课，不重抄全表）

| 现象 | 更像 | 用户话术 |
|------|------|----------|
| QACK Queued-for-resource | H-排（资源） | 「排上了，请勿连续猛按」 |
| QACK Queued-for-busy | H-排（被叫忙） | 「对方通话中，已排队」 |
| 资源/系统忙类最终 NACK | H-忙（系统不愿或不能再排） | 「现在系统忙，请稍后再试」 |
| 被叫忙且不排队 | 策略选择，未必是容量不足 | 查为何不排队 |

口诀：**QACK 是中间态，不是砖头砸手台。** 狂按 PTT 可能触发防刷，把 H-排弄成更难看的拒绝。

#### 4.2.5 优先级：标准给比特，不给算法

第 38 课原话气质：优先修饰可以进入 C_RAND；**TSCC 可以**管理队列让高优先更快「熟」——但**队列怎么管，规范不规定**（*procedures … are not prescribed*）。

所以：

- 「拨了 `*8` 还是慢」→ 先查**本网是否实现优先队列** → 常为 **H-优**，不是手台坏。  
- 紧急抢占（preemption）更是**产品/网管策略**；没有配置就没有魔法。  
- 对领导的诚实句：「优先码是门票上的印章；章响不响，看本网队列软件开没开。」

#### 4.2.6 短信 / USBD / 登记风暴吃控制容量

第 39 课：UDT 短信在 TSCC 上跑，一块块 30 ms 时隙堆上去。现场连锁：

```text
  群发短信 / 定位轮询过密 / 晨高峰登记潮
           ↓
  TSCC 时隙被小货车占满
           ↓
  登记变慢、Grant 变慢、甚至业务侧「看起来像死了」
           ↓
  贴纸 H-控（可次挂 H-配：轮询周期不合理）
```

反例：把「短信一多登记慢」当成鉴权失败（手册05）或 Hunt 失败（手册04）——两本账一对就露馅。

### 4.3 容量分诊最小公式卡（可复印）

```text
  同时可通话路上限 ≈ 2 ×（业务物理信道数）− 闭塞 − 被控制/数据长期占用的槽
  忙时是否越线？看：峰值占用、QACK 比例、投诉人数、金机对照
  控制是否越线？看：TSCC 利用率、登记时延、短信队列、Aloha 健康
  配置是否造忙？看：Hangtime、可用列表、Non-Dedicated 行为、优先策略开关
```

### 4.4 和弱项加餐的衔接

听不清、BER 差，是手册07 的梯子；**听得清但进不去房**，才是本篇。若高峰时 BER 也烂，可能是 H 与 F **叠加**——先把占用曲线和 BER 曲线**同窗对齐**（手册06 对时），再决定主贴纸。

## 5. 现场映射：用户原话 → H 子类；对话脚本；反例

### 5.1 原话 → 主子类

| 用户 / 调度原话 | 先问 | 主子类倾向 |
|-----------------|------|------------|
| 「排队排队，绿灯闪半天」 | 空口有无 QACK？随后有无 Grant？ | H-排（有 QACK）/ H-忙（最终资源拒） |
| 「忙音，金机也一样」 | 是否高峰？占用？ | H-忙 |
| 「就我这台不行，别人都好」 | 金机同点？非高峰？ | **离开 H**，回 A–E |
| 「短信群发后大家都登不上」 | TSCC 利用率？业务占用？ | H-控 |
| 「晚上没事，上班点必卡」 | 忙时窗口对齐排班 | H-忙 / H-配 |
| 「优先呼叫也不快」 | 本网优先队列开了吗？ | H-优 |
| 「紧急都插不进去」 | 抢占策略？真满还是未配置？ | H-优（+ 可能 H-忙） |
| 「加功率就能好」 | 占用曲线有没有？ | **拒绝该动作**；继续 H 或 F 分诊 |
| 「实验室好好的」 | 台架有无模拟忙时负载？ | G 过支持「非终端」；转 H |

### 5.2 值班对话脚本

#### 对话 A · 「先给我换一台机」

> 你：高峰吗？旁边同事同样吗？金机同点试过吗？  
> 若「都一样」→ 「这更像客房订满，换机加不出新房。我们先看占用和排队记录。」  
> 若「就我一台」→ 离开 H，走手册01–05。

#### 对话 B · 「优先功能坏了」

> 你：空口能看见优先相关请求吗？（有则终端侧大致发出去了）本网队列策略开了吗？  
> 「开了仍从不插队」→ 查策略/故障；「没开」→ **H-优 预期管理**，不是修手台。

#### 对话 C · 「短信业务有 Bug」

> 你：业务时隙空不空？TSCC 利用率高不高？  
> 「业务空、控制满」→ H-控；临时限非紧急短数据，再查轮询周期。

#### 对话 D · 「加功率」

> 你：加功率不加时隙。若五格梯子已过，加功率还可能制造互调/过载。本单走容量账。

#### 对话 E · 「QACK 是不是故障码」

> 你：QACK 是「排上了」的中间条，不是砖头。请勿连续猛按；看后面是 Grant 还是最终拒绝。

### 5.3 反例集（禁止清单）

| 反例 | 为什么有害 | 正确动作 |
|------|------------|----------|
| 加功率当扩容 | 不增加时隙；破坏干扰边界 | 占用/队列证据 → H |
| 单用户偶发忙就立项扩容 | 浪费；掩盖 A–E | 先金机+非高峰对照 |
| 金机也忙却坚持换终端 | 延误真扩容/改配 | 金机同忙 = 容量旁证 |
| 把 QACK 当 NACK 重装固件 | 制造更多 C_RAND 风暴 | 用户教育 + 看队列 |
| 只报全天平均占用 | 隐藏忙时 | 强制忙时窗口 |
| 台架无负载「证明容量正常」 | 台架默认证明不了忙时 | G 过转 H，不矛盾 |
| 一有忙就改鉴权/洗写频 | 拧错旋钮 | 两本账先填 |

### 5.4 40 分钟标准节奏（可复印）

```text
  0–5 min   记原话、时段、人数、金机
  5–15 min  拉业务占用 + 控制利用率（同窗对时）
  15–25 min 空口/网管抽样 QACK·Grant·登记时延
  25–35 min 定 H 子类；写插页 H；列短/长动作
  35–40 min 脱敏进总三联单；该不该开维护窗写清
```

## 6. 工作实例（10 个厚例，均教学虚构、已脱敏到 L3）

### 例 1 · 「上班点全组排队」→ H-忙 + H-排

现象：工作日 08:55–09:15 多组投诉排队。金机同站同样。  
观察：业务时隙峰值占用 ≈ 打满；QACK 资源排队密集；五格梯子抽测过。  
判定：主 H-忙，次 H-排。短措施：错峰非必要组呼；长措施：评估 +1 物理信道。  
证据：占用曲线 + 插页 H。

### 例 2 · 「就我这台忙音」→ 离开 H

现象：单机、非高峰。金机同点正常。  
观察：业务占用低；该机空口见登记类异常（指针回手册01）。  
判定：**不贴 H**；转贴纸 B/登记分诊。  
教训：规模证据 R3 不满足时禁止贴 H。

### 例 3 · 「短信群发后登记崩了」→ H-控

现象：调度群发通知后 10 分钟内登记失败投诉上升。  
观察：业务占用中等；TSCC 利用率冲高；短信队列堆积；鉴权 Reason 未成风暴主因。  
判定：H-控。临时限短数据并发；复盘轮询/群发策略。  
别误贴：手册05 鉴权主因（除非证据显示 K/PSN 真坏）。

### 例 4 · 「Hangtime 太长像一直占着」→ H-配

现象：话音间隙长，别人插不进同组；忙时加重。  
观察：EOT 后保留窗明显偏长；空闲时隙被礼貌窗吃掉。  
判定：H-配。维护窗A/B 测试缩短 Hangtime（可回滚）；记基线。  
禁令：不在忙时盲改。

### 例 5 · 「优先呼叫也不快」→ H-优

现象：指挥员拨优先修饰，体感与普通呼叫无异。  
观察：空口请求带优先味道；网管确认本网**未启用**优先队列。  
判定：H-优（预期落差）。对用户改话术；若业务需要再立项开策略——不是换机。

### 例 6 · 「Non-Dedicated 一忙前台就哑」→ H-配（+H-控）

现象：话务升高时登记/叫号变差，业务侧仍有空隙。  
观察：共享控制形态下控制角色频繁让路；Dedicated 对照站无此现象（教学对比）。  
判定：主 H-配，次 H-控。架构级讨论是否调整控制形态/加控制资源。

### 例 7 · 「金机也忙 = 基站坏了？」→ H-忙旁证

现象：班长要求换基站板。  
观察：射频三过；占用打满；邻站同频干扰指标不支持 F-同。  
判定：H-忙。换板无依据；扩容或话务治理才是正道。  
对接手册08：台架 G 过反而支持「非硬件随机坏」。

### 例 8 ·（对照）未看占用就贴「终端故障」→ 被打回

错误链：高峰多人忙 → 一线换了 6 台机 → 投诉不变 → 班长打回。  
纠偏：补 R3–R5；改判 H-忙；换机单作废。  
质检：手册06 证据等级——只有 E3 口述时不能结「终端故障」。

### 例 9 · 「紧急插不进」→ H-优 + 可能 H-忙

现象：演练紧急呼叫仍排队。  
观察：真满（H-忙）且紧急抢占未配置（H-优）。  
判定：双挂。先诚实披露策略能力；满负载下无抢占配置则无法「变出空房」。

### 例 10 · 「实验室正常、现场高峰挂」→ G 过转 H

现象：手册08 闭环①③过；现场早高峰复现忙。  
观察：台架无多用户负载注入；现场占用曲线漂亮地证明满。  
判定：贴纸 G（台架非根因）+ 主 H-忙。  
教训：G 不负责仿真整网 Erlang；别用实验室打脸容量单。

### 6.5 话务对齐会：15 分钟议程

```text

  2) Top 投诉原话 → 子类分布（3 min）
  3) 误贴统计：把 H 贴成 F/A–E 的单（3 min）
  4) 短措施效果：限短信 / 错峰 / Hangtime 试验（4 min）
  5) 是否触发扩容门槛（3 min）——门槛预先写在分诊卡封面
```

| # | 术语 | 白话 | 易错 |

| 2 | 容量 / Capacity | 系统能同时扛多少路 | ≠ 覆盖半径 |
| 3 | Erlang | 平均同时占用的「路数」单位 | ≠ 误码率 |
| 4 | Offered load | 砸进来的需求 | ≠ 已接通量 |
| 5 | Carried load | 实际扛下来的量 | 忙时二者缺口≈被挡/未完成 |
| 6 | GoS | 忙时被挡概率目标 | ≠ 「音质好不好」 |
| 7 | Busy hour | 最忙一小时 | ≠ 全天平均 |
| 8 | Blocking | 满了进不去 | ≠ 听不见 |
| 9 | Queueing | 满了先排队 | ≠ 死机 |
| 10 | Erlang-B | 不愿排队时的阻塞模型 | 有排队时气质偏 Erlang-C，本篇只借直觉 |
| 11 | Trunking efficiency | 合池共享比拆池更抗突发 | ≠ 「集群一定不忙」 |
| 12 | TSCC | 控制信道 / 前台 | ≠ 业务客房 |
| 13 | Payload | 业务信道 / 客房 | ≠ 前台叫号流 |
| 14 | Dedicated TSCC | 专用前台形态 | ≠ 永远不能带业务的口号绝对化 |
| 15 | Non-Dedicated TSCC | 控制与业务共享形态 | ≠ 「没有控制信道」 |
| 16 | Channel Grant | 房间号小票 | ≠ 已经在说话 |
| 17 | QACK | 排队中间条 | ≠ 最终故障码 |
| 18 | NACK（资源/忙类） | 最终拒绝（原因见第34课表，本篇不重抄） | ≠ 一律终端坏 |
| 19 | Hangtime | EOT 后保留窗，继续占槽 | ≠ Late Entry |
| 20 | 时隙 / Slot | 30 ms 一扇门；两扇/载波 | ≠ 物理频点本身 |
| 21 | 业务占用率 | 客房满度 | 与控制利用率分账 |
| 22 | 控制利用率 | 前台满度 | 短信也能把它打满 |
| 23 | UDT / 短信控制负荷 | 控制信道上的小货车 | ≠ 自动占业务信道 |
| 24 | 优先队列 | 网管策略，非标准强制算法 | 拨了优先码≠一定快 |
| 25 | Preemption / 抢占 | 紧急挤占资源的产品能力 | 未配置则无 |
| 26 | 贴纸 H | 话务/容量总类 | 须子类+证据 |
| 27 | H-忙/排/控/配/优 | 五子类 | 可主+次，勿一次贴全 |
| 28 | 插页 H | R1–R8 话务证据页 | 无占用曲线则弱 |

**易错观念十条**：

1. 「双时隙了就不会忙」→ 会；用户与时长决定 Erlang。  
2. 「加功率 = 扩容」→ 否。  
3. 「金机也忙 = 硬件坏」→ 高峰更像 H。  
4. 「QACK = 坏了」→ 中间态。  
5. 「实验室正常所以现场不是容量」→ 台架默认无忙时负载。  
6. 「优先码是标准保证插队」→ 策略未规定死。  
7. 「短信不占业务所以无限发」→ 吃 TSCC。  
8. 「全天平均 40% 很健康」→ 看忙时。  
9. 「Non-Dedicated 更省所以永远更好」→ 高话务可能饿死前台。  
10. 「一人偶发忙先扩容」→ 先 A–E。

## 9. 自测（10 题）+ 参考答案

**题 1.** 用户说「排队」，空口见 QACK Queued-for-resource，随后 Grant。主贴哪类？要不要换机？

**题 2.** 为什么「加功率」不能当话务单的短措施？

**题 3.** 控制容量与业务容量如何用两句话区分？各举一个用户原话。

**题 4.** 金机与多用户在高峰同样忙，更支持 H 还是「基站射频坏了」？还缺什么证据？

**题 5.** 拨了优先修饰仍然慢，规范层面你该先怀疑什么（H-优）？

**题 6.** 短信群发后登记变慢、业务占用却不高，优先哪一子类？

**题 7.** Hangtime 过长如何把「礼貌」变成 H-配？

**题 8.** 插页 H 的 R3、R4、R5 各挡住哪种误判？

**题 9.** 为什么手册08 台架 G 过，不能用来否定现场 H-忙？

**题 10.** 给出扩容门槛四要素（与 §7.1 对齐的最小集）。

### 参考答案

1. 主 **H-排**（资源排队）；若占用也打满可次挂 H-忙。**不要换机**；教育勿狂按；看 GoS 是否可接受。  
2. 功率不增加时隙/客房数；还可能恶化干扰（手册07 禁令）。  
3. 业务账=客房满不满（排队/忙音）；控制账=前台堵不堵（登记慢/短信后全卡）。  
4. 更支持 **H**；仍要占用曲线 + 梯子过 + 排除大规模干扰。缺占用就只是旁证。  
5. 本网**未实现**优先队列/抢占，或实现了但策略阈值导致体感不明显——先查策略，再查故障。  
6. **H-控**。  
7. 保留窗长期占槽 → 平均占用↑ → 同等呼叫下更易阻塞；忙时放大。  
8. R3 挡「单机误贴 H」；R4 挡「空喊扩容」；R5 挡「把 H-控当成 H-忙」。  
9. 常规台架无多用户忙时注入，证明不了整网 Erlang；G 过只排除「终端/台架剧本」类根因。  
10. 忙时峰值占用阈值 + 持续时间 + QACK/投诉规模 + 已排除 F/A–E（具体数字本网自填）。
